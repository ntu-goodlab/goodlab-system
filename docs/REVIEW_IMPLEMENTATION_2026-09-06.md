## 介面方向與已落實調整

以研究室工作介面為方向：明確的事項、狀態與下一步，減少裝飾與重複介紹。

- 一般成員首頁優先顯示自己的值日待辦與財產盤點，移除重複的值日摘要。
- 選取導覽改為較沉穩的深藍，減少面板陰影與圓角，精簡頁面重複副標。
- 「財產盤點」「連結你的成員資料」改用較直接的文案。
- 盤點使用有文字的狀態按鈕，避免點整列意外變更；排序表頭可使用鍵盤操作並提供 aria-sort。
- 手機篩選列可換行、財產名稱可折行；小按鈕增加觸控高度，設備聯絡資訊可直接展開。

這一輪是既有設計的整理，尚未全面統一所有 inline style、modal 或導覽。後續應以一般成員完成值日、管理員匯入與核帳的實際任務觀察，調整資訊密度，而非再次大量新增卡片、標籤與導覽層級。

## 尚未完成，依優先次序

1. **普通成員身分綁定與資料可見範圍。** 本地規則仍允許已驗證 Google 帳號認領未綁定 User，學號不足以證明身分；一個 UID 對應多個成員也尚未由規則防止。`members` 全文件目前仍可被所有已登入者讀取，包括 Google 身分欄位。需設計一次性邀請／可信任的身分驗證與 UID 唯一對應，並把公開名冊與私人身分資料分開；不能只靠隱藏畫面。
2. **值日排班的權威來源。** 完整清單提交已受規則限制，但普通成員建立週紀錄時的輪值歸屬仍主要由前端推算；規則只驗證 assigned_to 是自己，沒有證明該週真的輪到自己。應由可信任排程建立指定週的指派，再限制成員只能更新被指派紀錄。
3. **載入效能與模組邊界。** 初始 JavaScript 仍約 610 kB，多個集合使用即時訂閱；未實作依頁載入與依需求訂閱。下一步先拆行政模組與非即時歷史資料，保留首頁必要摘要，避免破壞跨頁計算與角色切換。
4. **帳務稽核與大批次恢復。** 保留 Created_At 不等於完整稽核；仍需修改歷史／沖銷流程。匯入已有逐批原子備份，尚缺備份復原介面、跨重新整理續傳與大量資料效能測試。
5. **跨系統輪值一致性。** GAS 與前端仍各自維護排程相關邏輯；新增回歸案例降低差異，但未完成共用規格／單一來源重構。

上述項目尚未達到正式驗收條件，不能宣稱「整站已安全」或用本地測試結果直接取代正式規則。
