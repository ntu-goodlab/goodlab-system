# 修復未核准的舊 Google 綁定

2026-09-09。舊成員保留 Google_UID，但沒有 member_access 時，原核准介面一律停用按鈕，儲存也直接要求遷移。已離校成員因此無法由管理員恢復，直接設 Admin 也無法成功。此次修復不自動核准任何正式帳號。

## 修復行為

- 相同 UID 與信箱的舊綁定可透過本人已送出的申請重新核准，不必先刪除綁定。
- 已離校者顯示「核對並恢復使用權限」。管理員必須勾選恢復在學／在職狀態才可送出；清空目前 Leave_Date、保留到 Previous_Leave_Dates，原子建立 User 授權與名錄。之後才可升 Admin。
- 交易重讀申請、綁定與成員狀態。UID／信箱不符、已有授權、確認後狀態變動時拒絕操作。
- 管理員可以修正尚未核准的舊成員資料，保留 Google 身分且角色限 User；此類儲存不建立授權，畫面明確說明仍須申請核准。
- 未核准的帳號直接升 Admin 會顯示具體處理方式。缺少授權文件時，解除或刪除舊綁定不再嘗試刪除不存在的授權。

規則僅增加管理員修正未授權舊成員的受限更新：UID／Google 信箱／顯示名稱／學號不變，User 角色，授權文件在交易前後均不存在。未新增任何讀取許可，Guest、離校與未核准帳號仍無實驗室資料權限。

## 驗證

85 項功能測試及 35 項 Firestore 規則測試通過；包含已離校舊綁定完整恢復、升降權、無授權資料的編輯／解除／刪除、身分衝突及狀態競爭。Browser 在 `preview:approved` 的 `?role=admin&recovery=1#/members` 假資料中驗證恢復按鈕、未勾選不可送出、勾選後成功核准與待辦消失。正式 Firebase 資料僅唯讀核對，帳號狀態由管理員透過新流程決定。
