# 管理員登入相容性修正（2026-09-07）

新版介面要求 admins/{uid}.student_id 與成員學號相同；歷史規則則只以 admins/{uid} 是否存在判斷管理員。未帶 student_id 的合法舊登錄因此可能在新版前端被當成一般成員。本次發布前未涵蓋舊登錄格式，是相容性驗收缺口。

修正保留現有規則與正式資料：

- 已綁定本人且 Role=Admin 的成員，若管理員登錄帶有 student_id，仍必須精確吻合。
- 登錄存在且沒有 student_id 時，監聽 accounting/goodlab-admin-permission-check 作唯讀權限查核。文件不必存在，也不會建立或修改；不使用回傳的文件內容。
- 只有來自伺服器、非快取的成功讀取，才能啟用舊登錄管理功能。該集合在舊版與候選規則均限管理員讀取。
- 權限被拒絕、登錄缺失或學號不符時不放行；登入／登出與帳號切換會取消舊監聽，延遲回應不得污染新帳號。
- 提示區分連線／讀取失敗、缺少登錄、學號不符與舊登錄未被現行規則授權。

驗證：76 項功能測試、18 項本地模擬器測試及建置通過。模擬器分別驗證歷史 UID 白名單模式與候選嚴格規則，確認不存在的查核文件可以只讀授權、不會產生寫入。假資料頁 `/?role=admin&legacyAdmin=1` 已實測管理員導覽與聘僱入口。

本次未讀取或修改使用者正式 admins 文件，因此不能僅憑舊提示斷言其實際欄位狀態；這項修正處理已由歷史程式與模擬器重現的舊格式相容問題。若更新後仍受阻，新提示可區分剩餘原因。Firebase 專案 IAM 擁有者身分與網站 Firebase Auth／Firestore 管理員登錄是不同的權限來源。
