# 六項使用回饋的本地實作

承接使用者對財產、維修、手冊、值日提交、公告／行事、聘僱的六項回饋。所有變更限於本地，沒有提交、推送、部署、正式資料操作或寄信。

## 本次行為

1. **財產清冊與年度盤點分開呈現。** 一般成員首頁的盤點待辦只在 `_SETTINGS_.IsOpen` 開啟時出現；移除常駐的盤點快捷入口。導覽改稱「財產清冊」，關閉盤點仍能搜尋財產名稱、編號與位置，維持唯讀。沒有新增自動計時或一週後強制關閉；年度盤點仍由管理員開關控制。
2. **維修紀錄先開放唯讀。** 一般成員可進入維修頁搜尋、篩選與開啟詳細資料。隱藏回報入口；讀取詳情不使用可編輯表單。新增、修改與刪除仍限 Admin，已新增模擬器測試。Firestore 讀取沿用目前儀器／財產的 `isSignedIn()` 邊界，並非伺服器驗證的名冊資格；嚴格限制已綁定成員仍依賴前一輪尚未完成的 UID 對應設計。
3. **儀器手冊。** 沿用現有 `Manual_Link` 欄位，有 HTTP(S) 網址才顯示「使用手冊」按鈕；管理員編輯時提供用途說明與網址檢查。按鈕在桌面與手機都可使用，設定另開分頁與 `noopener noreferrer`。預覽連結是示範頁，沒有假裝提供真實設備手冊。
4. **值日提交。** 將欠缺項目說明與提交按鈕收進同一區塊，桌面右側按鈕、手機靠右排列，取消橫跨整頁的藍色長條。尚有未完成項目時停用按鈕，旁邊列出缺項；全部完成才可提交。Firestore 完整性檢查仍保留。
5. **公告與行事編輯。** 公告／Meeting 改用集中對話框；公告先填標題與內容，再選成員可見性，連結、置頂及下架日期收進選填設定。卡片明確標示「編輯公告」「編輯 Meeting」，公告標題列提供「管理行事」。行事每筆直接有編輯按鈕，頂部直接新增，不再先切到另一個編輯列表；保留成員可見性提示，刪除放在編輯視窗。
6. **聘僱資訊與流程。** 預設人員列表，月份時程作為另一種檢視；新增入口使用「新增聘僱」，先選人員，再呈現計畫、期間與月額。無計畫時先導向新增計畫。依後續回饋移除整個實驗室的本學期各月申報金額與合計；計畫表合併識別資料，呈現餘額／超出金額與預算使用比例。月份時程區分「平均分攤」「申報金額」，後者可點選單月，包括已調整為 0 元的月份。

## 同時修正的聘僱資料問題

- 恢復基本月額時，使用 Firestore `deleteField()` 刪除該月調整，保留其他月份；避免巢狀 merge 留下舊值。
- 清空本學期預算時真正移除該學期欄位，保留其他學期及建立時間。
- 儲存完成後關閉人員／計畫／單月編輯畫面，不依賴快照到達時機。
- 即時更新保留同一人員、計畫、月份與學期的表單草稿；送出中暫緩重新繪製。重新整理不提供草稿持久保存，也不代表已實作多人編輯衝突合併。

## 驗證

- 功能測試 62 項通過，包括申報時程保留 0 元月份、表格儲存保留單月調整與建立時間、一般／特殊分攤期間、重疊計畫驗證。
- 本地模擬器測試 13 項通過，包括維修唯讀、單月調整清除與學期預算清除。
- 建置成功；主 JavaScript 仍約 616 kB，分包效能議題尚未處理。
- 實際操作本地假資料：盤點開關、維修唯讀詳情、公告及行事編輯、聘僱列表／月份／計畫視圖、0 元月份入口；驗證公告、人員聘僱、計畫、單月金額在資料更新後保留輸入。
- 手機 375px 檢查聘僱摘要、儀器手冊入口與值日提交區；聘僱摘要未造成整頁橫向溢出，寬表格仍在自身捲動容器內。
- 實際 Google 登入、正式手冊分享權限、Excel 匯出及正式資料規模未在此假資料預覽驗收。

執行方式見 [本地驗證](LOCAL_VALIDATION.md)。正式環境的維修唯讀需要相應前端與規則配套；仍須遵守 [第一輪修補紀錄](REVIEW_IMPLEMENTATION_2026-09-06.md) 的身分、排班權威來源與發布前相容性限制，不能直接把本地候選規則當成完成所有安全問題的正式版。

## 後續密度調整

- 人員聘僱改成每計畫一列的編輯表，直接輸入民國年月、計畫與基本月額；平均月薪與申報合計在列內即時更新。保留一次儲存此人的全部變更。
- 備註、特殊分攤日期與刪除收進各列「設定」；已有特殊分攤、單月調整或備註時，在計畫下顯示提示。一般分攤隨申報日期同步，既有不同分攤期間會自動勾選特殊設定。
- 新增列與刪除／復原保留其他欄位輸入，資料更新也保留展開狀態及草稿。表格提供原生 Tab 欄位切換，未實作 Excel 多格貼上或試算表公式。
- 桌面以緊湊表格呈現，375px 手機轉兩欄欄位；四個計畫假資料已驗證。
- 值日補充說明改為標題與文字分隔列，移除巢狀卡片、藍色左線與裝飾圖示；保留完整內容及廠商連結。
- 本輪重新執行 62 項功能測試及建置通過；沒有更動安全規則，上述 13 項模擬器測試為前輪結果。本地預覽不寫入正式資料。

## 聘僱未儲存保護與重試

- 人員、計畫與單月編輯統一比對初始欄位值與列結構；只有實際修改才提醒，改回原值可直接離開。切換人員、學期、檢視方式、其他頁面、取消及登出均受保護。瀏覽器返回時取消離開會還原聘僱網址；重新整理或關閉分頁使用瀏覽器原生提醒。
- 儲存中鎖定聘僱控制項並阻擋重複送出與畫面切換。失敗後恢復控制項、保留輸入及編輯狀態，允許直接重試；批次建立失敗也會解除鎖定。
- 同一次新增的聘僱／計畫重試沿用同一筆 ID，避免回應不確定時另建重複紀錄。此保護限於目前分頁的編輯階段。
- 帳號切換會清除編輯狀態，舊帳號尚未完成的儲存回應不操作新帳號畫面。
- 68 項功能測試與建置通過，主程式約 618 kB。增加取消切換、返回網址、欄位還原、重複送出、失敗重試、跨帳號回應及重新整理提醒案例。
- 瀏覽器實測三種編輯的儲存失敗、資料更新、再次儲存和還原欄位後取消。使用假資料預覽，儲存被刻意拒絕；成功路徑以測試替身驗證，未對正式資料寫入。
- 本輪範圍為聘僱三種編輯介面；其他功能尚未統一納入離開提醒。草稿未持久保存，強制關閉或確認放棄後不會自動復原。未部署。

## 表格內單月調整

- 每列「設定」新增本學期六個月份的金額與原因，與整張聘僱表格一起儲存，不需切換月份時程。留空沿用基本月額，0 元表示該月停聘，非預設金額須填原因。既有舊調整未修改時保持相容。
- 「恢復基本月額」清除該月輸入；既有月份的刪除用 Firestore deleteField，其他修改用單月欄位路徑寫入，保留未修改月份的並行更新與原建立時間。這不是整筆聘僱的衝突合併。
- 申報期間外的月份顯示唯讀與不套用提示；既有期間外調整保留，尚未儲存的期間外輸入不套用。未在本學期的月份仍從月份時程切換學期後編輯。
- 桌面六欄、手機兩欄。已驗證原因必填、恢復預設、即時總額／平均月薪、資料更新及儲存失敗後保留欄位。
- 71 項功能測試、14 項本地資料庫測試及建置通過；資料庫新增案例確認刪除九月調整、加入十一月調整時，不覆蓋另一人更新的十月金額。主程式約 622 kB。未操作正式資料或部署。
